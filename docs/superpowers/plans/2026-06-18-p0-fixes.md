# P0 Fixes Implementation Plan — Ping over SSH + Hub Update Badge

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make ping/latency config reach SSH-only agents, and make the hub's update badge + self-update honor the fork (`AGENT_REPO`) without the `--china-mirrors` 403 footgun.

**Architecture:** Three surgical hub-side changes. (1) Remove the WebSocket-only guard in `PushConfigToAll` so `sys.request`'s existing WS→SSH fallback carries ping config to every system. (2) Build the GitHub releases API URL from `AGENT_REPO` in `getUpdate` so the in-app badge checks the fork. (3) In `ghupdate`, defuse `UseMirror` for any non-upstream repo so fork self-update never hits the henrygd-only mirror. No entity, CBOR, migration, or protocol changes.

**Tech Stack:** Go 1.24, PocketBase, stdlib `net/http`, `testing` + `testing/synctest`, `github.com/stretchr/testify`, `httptest`.

```go
// shouldUseMirror decides whether the gh.beszel.dev mirror may be used for a
// self-update. The mirror proxies only the upstream henrygd/beszel repo; using
// it for any fork 403s on both the API call and the asset download. For forks
// the mirror flag is defused and the update runs over a direct GitHub
// connection (operators behind a restricted network set HTTPS_PROXY instead).
// An empty owner is treated as non-upstream because update() defaults it to
// "henrygd" only after this guard runs conservatively on the raw config.
func shouldUseMirror(useMirror bool, owner, repo string) bool {
	if !useMirror {
		return false
	}
	return owner == "henrygd" && repo == "beszel"
}
```

```go
// upstream default, so upstream behavior is unchanged.

	orig := os.Getenv("AGENT_REPO")

		if got != want {
			t.Fatalf("expected %q, got %q", want, got)
		}
	})
```

```go
// When AGENT_REPO is set to a valid "owner/repo", the badge checks the fork's
```

```go
// configPusher sends the monitor config to a single system. It is an interface
// so tests can verify PushConfigToAll attempts every system (including those
// with no WebSocket connection) without standing up real transports.
type configPusher interface {
	PushConfig(sys *System, cfg common.MonitorConfig)
}

// PushConfigToAll sends the current monitor config to every connected agent.
// Called when monitors are created/updated/deleted. Systems are NOT filtered by
// transport: sys.request falls back from WebSocket to SSH, so an agent
// reachable only via SSH still receives ping targets.
func (sm *SystemManager) PushConfigToAll() {
	cfg := loadMonitorConfig(sm.hub)
	for _, sys := range sm.systems.Values() {
		sm.configPusher.PushConfig(sys, cfg)
	}
}

// PushConfig is the real configPusher implementation: pushes to one agent in a
// goroutine with a 5s timeout, logging failures at debug.
func (sm *SystemManager) PushConfig(sys *System, cfg common.MonitorConfig) {
	go sm.pushConfigToSystem(sys, cfg)
}
```

## Notes for the implementer

- **Run order:** Tasks 1 and 2 are independent; Task 3 is independent of both. Any order works. The plan lists G3 → G2 → G1 because each is slightly more involved than the last.
- **`-tags=testing` is mandatory** for every `go test` invocation. `make test` adds it for you; direct `go test` calls do not.
- **Do not touch** entity structs, CBOR tags, migrations, or `MinVersion*` constants — these fixes are hub-side routing only.
- **Upstream parity:** After Task 2 and Task 3, an install with `AGENT_REPO` unset must behave identically to upstream for the update badge and self-update. Re-read the test cases in Task 1 (`{"upstream with mirror", true, "henrygd", "beszel", true}`) and Task 2 (`"unset returns empty"`) — they encode this contract.
- **G1 test seam rationale:** `sys.request` depends on real SSH/WS transports (`WsConn`, `sshTransport`, `sshConfig`), none of which are mockable without large refactors. The `configPusher` interface is the smallest seam that makes "all systems are attempted" directly testable while leaving production behavior (`go sm.pushConfigToSystem(...)`) identical. If a reviewer prefers no seam, the alternative is to accept G1 as untested (manual verification only) — but the seam is small and idiomatic for this codebase's test style.
